# AGENTS.md

## Проект
- Фронтенд: React, TypeScript, Vite. Бэкенд: Java 17+, Spring Boot.
- Сейчас бронирования работают только в демо-фронтенде и хранятся в состоянии страницы; backend предоставляет только `GET /api/health`.
- Для будущих бронирований учитывать окно 14 календарных дней, рабочие часы, часовой пояс и длительность; запрещать пересечения, разрешать старт в момент окончания предыдущей встречи и защищать от конкурентной записи.

## Работа с кодом
- Перед изменением API проверьте наличие исходного контракта и команд генерации. Если они есть, обновляйте контракт и регенерируйте SDK/OpenAPI; не редактируйте сгенерированные файлы вручную.
- Не предполагайте команды разработки: сверяйтесь с `mise.toml`, манифестами и скриптами проекта.
- Перед завершением запускайте релевантные проверки; полный набор: `mise run check`.
- Запуск бэкенда: `cd backend && mvn spring-boot:run`.
- Контрактная цепочка обязательна: TypeSpec → OpenAPI → сгенерированный SDK → серверный код → frontend, и при изменении контракта сначала правится контракт, затем генерируется артефакт, затем меняются обе стороны реализации.
- Все обращения фронтенда к API идут только через сгенерированный клиентский SDK; ручной `fetch` рядом с данным SDK запрещён, если контракт уже определён.
- Сгенерированные артефакты и пути: `typespec/**`, `openapi/**`, `backend/**/generated/**` и `frontend/src/api/**` (или эквивалентные пути, заданные командой генерации). Ручное редактирование этих файлов запрещено; изменения вносятся только через генерацию из контракта.
- Если артефакты коммитятся, CI должен повторять генерацию и проверять, что в репозитории нет несгенерированных изменений. Если артефакты не коммитятся, CI должен генерировать их из чистого состояния перед сборкой и тестами.

## Коммиты
- Используйте Conventional Commits: `feat:`, `fix:`, `chore:`, `refactor:`, `test:` или `docs:`.
- Каждый коммит реализации обязан ссылаться на закрываемый тикет: `feat: запись на свободный слот (#12)`.
- Ветка реализации должна собирать изменения по нескольким связанным тикетам в одну общую ветку, а не по отдельным веткам без объединения.
